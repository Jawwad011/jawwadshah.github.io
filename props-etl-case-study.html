CASE STUDY • 02

PROPS ETL Validation

A source-to-target data validation workflow designed to identify record-level and field-level discrepancies during ETL processes.

Python Pandas pyodbc SQL Server Excel

THE PROBLEM

How do you know the ETL worked correctly?

Data was transferred from a source database into a target database through an ETL process.

A reliable validation mechanism was required to determine whether records and individual fields in the target matched the expected source data.

Manual comparison of large datasets would be time-consuming and difficult to maintain.

DATA FLOW

Comparing source data with ETL output.

01

Source

Original project database containing the expected records.

→
02

ETL Process

Data transformation and loading into the target environment.

→
03

Target

Database containing the transformed ETL output.

VALIDATION APPROACH

Automated comparison at multiple levels.

01

Extract

Retrieved source and target datasets using SQL Server connections through Python and pyodbc.

02

Align

Matched records using the appropriate participant or screening identifiers for each validation table.

03

Compare

Used Pandas-based comparisons to identify missing records, duplicate records and field-level differences.

04

Report

Generated a structured validation output showing which records and fields required investigation.

VALIDATION LOGIC

Finding the exact data discrepancy.

Record Validation

Checked whether expected source records existed in the target dataset.

Duplicate Detection

Compared records to identify unexpected duplicate rows in the validation dataset.

Field Comparison

Compared corresponding fields between source and target records to identify specific value mismatches.

Cutoff-Based Validation

Applied an ETL timing cutoff so validation was performed against data expected to have completed processing.

TECHNOLOGY

Python connected the validation workflow.

SQL + Python

SQL Server was used to retrieve the required datasets while Python provided the automation layer for comparison and validation.

Pandas was used to manipulate and compare datasets, while pyodbc provided the database connection between Python and SQL Server.

OUTCOME

Moving from manual checking to repeatable validation.

Automated Comparison

Large source and target datasets could be compared programmatically rather than manually row by row.

Field-Level Visibility

Validation results could identify the specific field where a mismatch occurred.

Repeatable QC

The validation workflow could be executed repeatedly as part of the ETL quality-control process.
